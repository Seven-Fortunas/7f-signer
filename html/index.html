Start From device To device

This page moves ceremony files between this computer or phone and a 7F SeedSigner by animated QR codes. It runs entirely in this browser: nothing is uploaded.

From device

Use it when the device shows a QR: it is exporting a key, a certificate or a signature.

  1. Open From device and allow the camera.
  2. Fill most of the camera view with the device's QR and hold steady. Parts arrive in any order; the grid turns green as they do.
  3. Compare what the page shows with the device's screen: the subject key id and, for a Root key, the root pin.
  4. Press Save. The page names the folder sf-wallet-gov uses, ~/7fchain/<network>/governance/root/outbox or …/devfund/outbox; keep Root and dev-fund files apart. NOT SAVED means the file name did not match the content: scan again, never rename by hand.
  5. Save summary (optional) writes <ski>.txt, a record for you. Send the file, not the summary.

To device

Use it when the device asks you to scan a file.

  1. On the device, open the menu below and go on to its scan step.
  2. Open To device and choose the file, or drop it on the page. It stays in this browser.
  3. Read the fields the page shows: the device will show the same ones on its review pages. Compare them with what the coordinator told you.
  4. Press Show QR to the device, turn the screen brightness up, and point the device's camera at it. If the device misses parts, press Slower, or Pause and step with the arrows. Done closes the player.
  5. Check every review page on the device. The device is the authority, not this page: its Canonical digest must match the coordinator's digest for the file. If it does not, stop and call.

How the root pin and the subject key id are made

Verification key (vk)
The public half of an ML-DSA-65 key: 1952 bytes. A .vk file holds it as 3904 lowercase hex characters and a newline.
Root pin
SHA-256 of the 1952 key bytes (the decoded bytes, not the hex text): 64 hex. For a Root key only, as sf-wallet-gov prints it. Read it aloud by phone from the device's screen and compare it with the coordinator's record. A pin written in a file proves nothing: whoever could change the file could change the pin.
Subject key id (ski)
The first 20 bytes of the same hash, its first 40 hex (RFC 7093 method 1), for every key, shown in groups of four. It names every file. A certificate's ski is that of the key it certifies. These are the values sf-wallet-gov prints.
Seed label
The device names a loaded phrase by the first 8 hex of its testnet Root ski at index 0. Check it before each step.

To recompute both from a .vk file:

xxd -r -p <ski>.vk | sha256sum

The output is the hash (for a Root key, its root pin). Its first 40 hex characters are the ski, and must equal the file name.

Which key names each file

  • <ski>.vk: the key itself.
  • root-<ski>.pem: the Root key it certifies (it signs its own certificate).
  • <ski>.genesis, <ski>.devfund: the Root key that signed. The dev-fund definition is signed by the Root key, not the dev-fund key.
  • deputy-<ski>.pem: the Root that issued it, not the Deputy. Each Root's certificate for the same Deputy has a different name.

Key index

Every Root and dev-fund step on the device asks for the key index, sf-wallet-gov's --index. Choose Index 0 (default). The key is derived at root/<network>/<index>/ml-dsa/v1 (dev-fund: devfund/<network>/<index>/ml-dsa/v1), so another index is a different key with a different ski. Use Other index only for a key that was made at that index; the device warns once and shows the index under the ski. Keep one phrase per Root key.

How a file travels as QR

  • To the device: a JSON config goes byte for byte; a .pem goes as its DER bytes (the decoded base64).
  • From the device: each export is a small JSON envelope naming its kind, its file name and its content. The page checks the name against the content before it saves.
  • Both ways, the bytes are compressed and split into BBQr parts of at most 300 characters, one QR each. The player shows each for 1.2 s and loops, so a missed part comes round again.
